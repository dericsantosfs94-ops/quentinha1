# Migração do schema da Cantina do Chalé para Supabase/PostgreSQL

Este documento converte o modelo atual de `drizzle/schema.ts`, originalmente definido para MySQL/TiDB, para PostgreSQL/Supabase.

> **Observação importante sobre chaves estrangeiras:** o schema Drizzle atual possui os campos `categoryId` e `productId`, mas não declara relações `references(...)` explicitamente. O SQL abaixo inclui as foreign keys recomendadas para preservar a integridade dos dados no Supabase.

## 1. SQL completo das tabelas

```sql
-- Extensão opcional para gerar UUIDs caso o projeto use UUID no futuro.
-- O schema atual usa IDs inteiros autoincrementais, portanto ela não é obrigatória.
create extension if not exists pgcrypto;

-- Função usada para atualizar updated_at automaticamente.
create or replace function public.set_updated_at()
returns trigger
language plpgsql
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

create table if not exists public.users (
  id integer generated by default as identity primary key,
  open_id varchar(64) not null unique,
  name text,
  email varchar(320),
  login_method varchar(64),
  role text not null default 'user',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  last_signed_in timestamptz not null default now(),
  constraint users_role_check check (role in ('user', 'admin'))
);

create table if not exists public.menu_categories (
  id integer generated by default as identity primary key,
  name varchar(120) not null,
  slug varchar(120) not null unique,
  icon varchar(40) not null default 'utensils',
  sort_order integer not null default 0,
  active boolean not null default true,
  created_at timestamptz not null default now()
);

create table if not exists public.menu_products (
  id integer generated by default as identity primary key,
  category_id integer not null,
  name varchar(160) not null,
  description text not null,
  price numeric(10, 2) not null,
  image_url text,
  available boolean not null default true,
  featured_of_day boolean not null default false,
  sort_order integer not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint menu_products_price_check check (price >= 0),
  constraint menu_products_category_fk
    foreign key (category_id)
    references public.menu_categories(id)
    on update cascade
    on delete restrict
);

create table if not exists public.menu_product_options (
  id integer generated by default as identity primary key,
  product_id integer not null,
  name varchar(160) not null,
  description text,
  price_delta numeric(10, 2) not null default 0.00,
  available boolean not null default true,
  sort_order integer not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint menu_product_options_price_check check (price_delta >= 0),
  constraint menu_product_options_product_fk
    foreign key (product_id)
    references public.menu_products(id)
    on update cascade
    on delete cascade
);

create table if not exists public.restaurant_settings (
  id integer generated by default as identity primary key,
  is_open boolean not null default true,
  updated_at timestamptz not null default now()
);

-- Equivalente ao onUpdateNow() do Drizzle para tabelas com updatedAt.
drop trigger if exists users_set_updated_at on public.users;
create trigger users_set_updated_at
before update on public.users
for each row execute function public.set_updated_at();

drop trigger if exists menu_products_set_updated_at on public.menu_products;
create trigger menu_products_set_updated_at
before update on public.menu_products
for each row execute function public.set_updated_at();

drop trigger if exists menu_product_options_set_updated_at on public.menu_product_options;
create trigger menu_product_options_set_updated_at
before update on public.menu_product_options
for each row execute function public.set_updated_at();

drop trigger if exists restaurant_settings_set_updated_at on public.restaurant_settings;
create trigger restaurant_settings_set_updated_at
before update on public.restaurant_settings
for each row execute function public.set_updated_at();

create index if not exists menu_categories_active_sort_idx
  on public.menu_categories (active, sort_order, name);

create index if not exists menu_products_public_sort_idx
  on public.menu_products (available, sort_order, name);

create index if not exists menu_products_category_idx
  on public.menu_products (category_id);

create index if not exists menu_products_featured_idx
  on public.menu_products (featured_of_day)
  where featured_of_day = true;

create index if not exists menu_product_options_product_sort_idx
  on public.menu_product_options (product_id, available, sort_order, name);
```

### Mapeamento dos tipos

| Schema atual Drizzle/MySQL | PostgreSQL/Supabase usado |
|---|---|
| `int` | `integer generated by default as identity` |
| `varchar(n)` | `varchar(n)` |
| `text` | `text` |
| `decimal(10, 2)` | `numeric(10, 2)` |
| `boolean` | `boolean` |
| `timestamp` | `timestamptz` |
| `mysqlEnum('user', 'admin')` | `text` com `check` |
| `autoincrement()` | `generated by default as identity` |
| `defaultNow()` | `default now()` |
| `onUpdateNow()` | trigger PostgreSQL `set_updated_at()` |

Os nomes foram convertidos de camelCase para snake_case, que é a convenção mais comum no Supabase. Se o frontend ou backend quiser manter os nomes camelCase, é possível criar views ou fazer alias nas consultas.

## 2. Consulta equivalente ao `listMenu()` público

A função atual do projeto faz quatro consultas separadas:

1. categorias ativas, ordenadas por `sortOrder` e `name`;
2. produtos disponíveis, ordenados por `sortOrder` e `name`;
3. opções disponíveis, ordenadas por `sortOrder` e `name`;
4. a primeira configuração de `restaurant_settings`.

Depois, o código associa as opções ao produto em memória. No Supabase/Postgres, uma única consulta pode retornar um JSON aninhado:

```sql
select
  coalesce(
    jsonb_agg(
      jsonb_build_object(
        'id', c.id,
        'name', c.name,
        'slug', c.slug,
        'icon', c.icon,
        'sortOrder', c.sort_order,
        'active', c.active
      )
      order by c.sort_order, c.name
    ) filter (where c.id is not null),
    '[]'::jsonb
  ) as categories,
  coalesce(
    jsonb_agg(
      jsonb_build_object(
        'id', p.id,
        'categoryId', p.category_id,
        'name', p.name,
        'description', p.description,
        'price', p.price,
        'imageUrl', p.image_url,
        'available', p.available,
        'featuredOfDay', p.featured_of_day,
        'sortOrder', p.sort_order,
        'options', coalesce(p.options, '[]'::jsonb)
      )
      order by p.sort_order, p.name
    ) filter (where p.id is not null),
    '[]'::jsonb
  ) as products,
  coalesce((select rs.is_open from public.restaurant_settings rs order by rs.id limit 1), true) as "isOpen"
from public.menu_categories c
left join lateral (
  select
    p.*,
    coalesce(
      (
        select jsonb_agg(
          jsonb_build_object(
            'id', o.id,
            'productId', o.product_id,
            'name', o.name,
            'description', o.description,
            'priceDelta', o.price_delta,
            'available', o.available,
            'sortOrder', o.sort_order
          )
          order by o.sort_order, o.name
        )
        from public.menu_product_options o
        where o.product_id = p.id
          and o.available = true
      ),
      '[]'::jsonb
    ) as options
  from public.menu_products p
  where p.category_id = c.id
    and p.available = true
) p on true
where c.active = true;
```

Para um retorno mais simples e compatível com o formato atual da API, também é possível fazer três consultas no backend Supabase:

```ts
const [{ data: categories }, { data: products }, { data: options }, { data: settings }] = await Promise.all([
  supabase
    .from('menu_categories')
    .select('*')
    .eq('active', true)
    .order('sort_order', { ascending: true })
    .order('name', { ascending: true }),
  supabase
    .from('menu_products')
    .select('*')
    .eq('available', true)
    .order('sort_order', { ascending: true })
    .order('name', { ascending: true }),
  supabase
    .from('menu_product_options')
    .select('*')
    .eq('available', true)
    .order('sort_order', { ascending: true })
    .order('name', { ascending: true }),
  supabase
    .from('restaurant_settings')
    .select('is_open')
    .order('id', { ascending: true })
    .limit(1)
    .maybeSingle(),
]);

const productsWithOptions = (products ?? []).map((product) => ({
  ...product,
  categoryId: product.category_id,
  imageUrl: product.image_url,
  featuredOfDay: product.featured_of_day,
  options: (options ?? [])
    .filter((option) => option.product_id === product.id)
    .map((option) => ({
      ...option,
      productId: option.product_id,
      priceDelta: option.price_delta,
    })),
}));

return {
  categories: categories ?? [],
  products: productsWithOptions,
  isOpen: settings?.is_open ?? true,
};
```

## 3. Dados iniciais de referência

Os três produtos abaixo reproduzem o padrão dos dados provisórios atuais. Eles dependem da existência da categoria `Pratos caseiros`.

```sql
insert into public.menu_categories (name, slug, icon, sort_order, active)
values ('Pratos caseiros', 'pratos-caseiros', 'soup', 0, true)
on conflict (slug) do nothing;

insert into public.restaurant_settings (is_open)
select true
where not exists (select 1 from public.restaurant_settings);

insert into public.menu_products
  (category_id, name, description, price, image_url, available, featured_of_day, sort_order)
select
  c.id,
  v.name,
  v.description,
  v.price,
  v.image_url,
  true,
  v.featured_of_day,
  v.sort_order
from public.menu_categories c
cross join (
  values
    (
      'Prato da foto 01',
      'Prato feito com arroz à jardineira, farofa e filés empanados. Composição provisória para edição no painel.',
      25.00::numeric,
      null::text,
      true,
      0
    ),
    (
      'Prato da foto 02',
      'Prato feito com proteína ensopada, legumes coloridos e farofa. Composição provisória para edição no painel.',
      25.00::numeric,
      null::text,
      false,
      1
    ),
    (
      'Carne acebolada com fritas',
      'Carne acebolada acompanhada de batata frita e farofa. Composição provisória para edição no painel.',
      25.00::numeric,
      null::text,
      false,
      2
    )
) as v(name, description, price, image_url, featured_of_day, sort_order)
where c.slug = 'pratos-caseiros';
```

Para associar fotos reais, substitua `null` em `image_url` pelas URLs retornadas pelo storage do Supabase Storage, por exemplo:

```sql
update public.menu_products
set image_url = 'https://SEU-PROJETO.supabase.co/storage/v1/object/public/menu-products/prato-01.webp'
where name = 'Prato da foto 01';
```

## 4. Pontos de atenção na migração

O login atual usa Manus OAuth e não é automaticamente substituído pelo Supabase Auth apenas pela migração das tabelas. Se o frontend for para a Vercel, será necessário escolher entre manter o provedor de autenticação atual ou migrar também o login do admin para Supabase Auth.

O storage de imagens também precisa ser migrado separadamente. O SQL cria apenas as referências `image_url`; ele não transfere arquivos. No Supabase, crie um bucket, por exemplo `menu-products`, configure as políticas de leitura pública ou assinada e adapte o upload do painel para `supabase.storage.from('menu-products').upload(...)`.

Por fim, o schema atual não salva pedidos: o checkout apenas monta uma URL para o WhatsApp. A migração acima cobre somente as cinco tabelas existentes solicitadas e não cria histórico de pedidos.
